# 评测报告

## 评测目标

评测关注产品是否稳定完成任务，而不只判断模型回答是否“看起来合理”。核心维度包括条件抽取、状态继承、工具顺序、数据筛选、异常恢复、输出渲染与成本边界。

## 核心案例

| 类别 | 输入/场景 | 预期行为 |
| --- | --- | --- |
| 信息缺失 | “我想在港区巡礼” | 补问起点、时长、用餐和成员偏好 |
| 明确短答 | “不需要用餐” | 一次写入，不重复追问 |
| 成员两阶段 | “我想限定成员” | 继续询问具体姓名 |
| 成员不限 | 从具体成员改为“不限” | 覆盖旧成员条件 |
| 新区域 | 旧行程后输入“我想在新宿区巡礼” | 清空旧起点、时间、用餐、成员 |
| 同名地点 | “新宿站” | 解析为东京新宿，拒绝山形同名结果 |
| 数据刷新失败 | 线上源不可用 | 保留快照并声明状态 |
| 空结果 | 当前筛选无匹配 | 不宣称现实中不存在，提供可恢复选项 |
| 输出格式 | 模型返回标题、列表、表格 | 转换为安全网页组件，不显示 Markdown 源码 |
| 公开限额 | 超过日次数 | 返回明确限额提示，不再调用模型 |
