# Agent 设计与边界

## 决策循环

每轮输入先更新结构化行程状态。若信息不完整，Agent 只追问缺失项；完整后依次解析起点、查询地点、处理餐厅授权、计算路线。工具结果会回到模型用于生成自然语言解释，结构化路线则直接交给前端组件。

## 模型负责

- 理解用户的自然语言、同义表达与上下文；
- 决定调用哪个工具及其参数；
- 根据结构化结果生成简短解释和下一步建议。

## 后端强制执行

- 未获得同意不得查询普通餐厅；
- 未补全必要信息不得搜索或规划；
- 地点只能来自受控数据源；
- 起点解析失败时不得猜坐标；
- 限制工具步数、消息长度、上下文长度和公开 Demo 次数。

## 为什么不是简单 Workflow

工具和硬规则是确定的，但调用顺序会根据用户信息动态改变：条件完整时可直接检索；信息缺失时先补问；没有巡礼餐厅时增加授权分支；地点过少时产生放宽建议；用户中途修改区域时重置状态。模型承担自然语言到状态/工具的动态决策，后端保证不可违反的业务规则。

## 数据链路

地点加载采用“线上刷新 + 已验证快照”策略。刷新数据需要通过非空、唯一 ID、名称、地址和坐标校验；刷新失败时继续使用最近可用快照，并在页面标注更新时间与状态。
